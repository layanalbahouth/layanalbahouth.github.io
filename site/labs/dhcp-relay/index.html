The PC that couldn’t get an IP: DHCP across a router

The DHCP server was on. The address pool was right. The cables were green. And still, every PC came up with an address starting with 169.254. I built this one in Cisco Packet Tracer on purpose, to watch the problem happen and then fix it.

The network

DeviceInterfaceAddress
Router1G0/0 (towards the PCs)192.168.10.1/24
Router1G0/1 (towards the server)192.168.20.1/24
Server0–192.168.20.10/24, gateway 192.168.20.1
PC0 / PC1–DHCP

On Server0, the DHCP service has a pool for the PCs’ network: starting at 192.168.10.100, mask 255.255.255.0, gateway 192.168.10.1, DNS 192.168.20.10.

The problem

With the PCs set to DHCP, this is what PC0 showed:

IPv4 Address ...... 169.254.55.39
Subnet Mask ....... 255.255.0.0
Default Gateway ... 0.0.0.0
DNS Server ........ 0.0.0.0

A 169.254.x.x address is one the PC gives itself when no DHCP server answers. It’s only good for the local link, so with no gateway, the PC can’t reach anything outside its own network.

The cause

A PC looking for an address doesn’t know where the DHCP server is, so it sends its request as a broadcast to everyone on its own network. Routers don’t forward broadcasts by default. The request reached Router1’s G0/0 and stopped there. The server never saw it, so it never answered.

Nothing was wrong with the server. The request just couldn’t reach it.

The fix

One command on the interface that receives the PCs’ requests tells the router to forward them to the server:

interface g0/0
 ip helper-address 192.168.20.10

With this, Router1 acts as a DHCP relay agent: it takes the broadcast and sends it on to the server as a normal unicast packet.

Checking it works

After switching the PC to Static and back to DHCP, it got a real lease:

DHCP request successful.
IPv4 Address ...... 192.168.10.100
Subnet Mask ....... 255.255.255.0
Default Gateway ... 192.168.10.1
DNS Server ........ 192.168.20.10

That’s the first address in the pool. On the router, show ip interface g0/0 confirms the setting:

Helper address is 192.168.20.10

And a ping from PC0 to the server got 4 out of 4 replies.

What I took from it

When a PC shows 169.254, the PC itself is usually fine: it asked for an address and nobody answered. The useful question is where the request stopped. If the DHCP server lives on another network, the router between them needs a helper address on the clients’ side.

One thing that tripped me up while building it: I first gave the server 192.168.20.1, the same address as the router, and the router logged a duplicate address warning. Worth checking before blaming DHCP.

الملخص: الأجهزة أخذت عناوين تبدأ بـ169.254 لأن سيرفر الـDHCP في شبكة ثانية خلف الراوتر. الجهاز يرسل طلب العنوان broadcast، والراوتر ما يمرر الـbroadcast، فالطلب ما وصل للسيرفر. الحل أمر واحد على منفذ الراوتر اللي جهة الأجهزة: ip helper-address 192.168.20.10، وبعده أخذت الأجهزة عناوينها من السيرفر.
